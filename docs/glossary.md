# 用語集

このリポジトリの文書とコードで使う用語の一覧です。外部サービスの用語は、そのサービスの公式ドキュメントの表記に合わせています。書き方のルールは、開発の進め方([CONTRIBUTING.md](../CONTRIBUTING.md#用語と文の書き方))の「用語と文の書き方」にあります。

「以前の表記」は、この用語集を作る前の文書、Issue、PR で使っていた表記です。過去の記録を読むときに参照してください。新しい文書では使いません。

画面に表示する文言(「購入を確定する」「代金を確定する」「発送を知らせる」などのボタン名)は、この用語集の対象外です。

## 決済(Stripe)

| 用語 | 意味 | 以前の表記 |
|---|---|---|
| オーソリ | カードの利用枠を確保すること。この時点では売上は確定しない。有効期限がある | 仮押さえ |
| キャプチャー | オーソリした金額を、売上として確定すること | 代金の確定 |
| オーソリのキャンセル | キャプチャーせずに、オーソリを取り消すこと | 仮押さえの取り消し |
| 3D セキュア | カード決済で、カード保有者の本人確認を行う認証 | 本人認証 |
| Checkout Session | 1回の購入手続きを表す Stripe のオブジェクト | — |
| Payment Element | Stripe が提供するカード情報の入力フォーム。カード情報は本サイトのサーバーを経由しない | カードの入力欄 |
| 連結アカウント | Stripe Connect で、プラットフォームに接続した販売者の Stripe アカウント。本サイトでは、生産者ごとに1つ作成する | 生産者の Stripe のアカウント |
| プラットフォームアカウント | 連結アカウントを管理する側の Stripe アカウント。本サイトでは、管理者のアカウント | 管理者(プラットフォームのアカウント) |
| ダイレクト支払い | 連結アカウント上に直接作成する支払い。代金はプラットフォームアカウントを経由しない | — |
| アプリケーション手数料 | 支払いごとに、プラットフォームアカウントが受け取る手数料(`application_fee_amount`) | — |
| 入金 | Stripe の残高から、銀行口座に振り込まれること(payout) | — |
| 送金 | Stripe アカウントの間で資金を移動すること(transfer)。本サイトでは使わない | — |
| 埋め込みコンポーネント | Stripe Connect が提供する UI 部品。本サイトのページに埋め込み、生産者がアカウント登録や残高の確認に使う | 画面部品、埋め込みの部品 |
| 不審請求の申し立て | カード保有者が、カード発行会社に支払いの取り消しを求めること。カード業界では「チャージバック」と呼ぶ。文書では「不審請求」と略す | — |
| 照会 | 不審請求の申し立ての前に、カード発行会社が取引の情報を求める手続き | — |
| 反証資料 | 不審請求の申し立てに反論するために提出する資料 | 証拠 |
| サンドボックス | Stripe のテスト用の環境。本番環境の資金とデータに影響しない | — |
| 公開可能キー | ブラウザのコードに含めてよい Stripe の API キー | 公開してよい鍵 |
| シークレットキー | サーバーだけが持つ Stripe の API キー | 秘密の鍵、秘密鍵 |
| 冪等キー | 同じリクエストを再試行しても、処理が1回だけ実行されるように、リクエストに付ける値(`Idempotency-Key`) | 同じ鍵 |

## Webhook

| 用語 | 意味 | 以前の表記 |
|---|---|---|
| Webhook | 外部サービスが、イベントの発生を本サイトのサーバーに HTTP リクエストで通知する仕組み | 知らせ(Stripe の知らせ、メールを送るサービスの知らせ) |
| イベント | 外部サービスで起きた出来事を表すデータ。Webhook で届く | 出来事、知らせ |
| イベントタイプ | イベントの種別(例: `charge.dispute.created`) | 知らせの種類 |
| Webhook エンドポイント | Webhook を受信する URL | 知らせを受ける入口 |
| 署名シークレット | Webhook の署名の検証に使う値 | 知らせの署名の鍵 |
| 照合 | Stripe の状態を定期的に取得し、データベースの状態を合わせる処理 | 突き合わせ |
| 冪等 | 同じ処理を何度実行しても、結果が変わらないこと | 何度受けても同じ結果になる |

## データベースと Supabase

| 用語 | 意味 | 以前の表記 |
|---|---|---|
| Supabase Auth | Supabase の認証機能 | Supabase の認証 |
| Supabase Storage | Supabase のファイル保存機能 | ファイルの保存 |
| バケット | Supabase Storage の中の、ファイルの保存先の単位 | 置き場所 |
| Data API | テーブルと関数を HTTP で公開する Supabase の API | データの口、データベースの口 |
| RLS ポリシー | テーブルの行ごとにアクセスを制御するルール。PostgreSQL の Row Level Security(RLS)で定義する | 行ごとの決まり |
| ロール | PostgreSQL の権限の単位。Supabase は `anon`、`authenticated`、`service_role` を用意している | 立場 |
| publishable key | Supabase の API キーのうち、公開してよいもの。本サイトでは、ブラウザに渡さない | 公開してよい鍵 |
| secret key | Supabase の API キーのうち、RLS ポリシーを適用せずにアクセスできるもの。サーバーだけが持つ | 管理用の鍵、秘密の鍵 |
| レガシー API キー | Supabase の以前の形式の API キー(`anon`、`service_role`)。本サイトでは無効にする | 旧来の鍵 |
| Admin API | secret key で呼び出す、ユーザー管理用の Supabase Auth の API | 管理用の操作 |
| エンティティ | データモデルの中で、データを持つ対象(例: 注文、商品、生産者) | 実体 |
| 属性 | エンティティが持つ項目 | 持つもの |
| テーブル | データベースの表 | 表 |
| トランザクション | 複数の書き込みを、すべて実行するか、すべて実行しないかのどちらかにする仕組み | いくつかの行を一度に変える書き込み |
| ローカル環境 | 開発者の PC 上の実行環境 | 手元 |

## 認証とセキュリティ

| 用語 | 意味 | 以前の表記 |
|---|---|---|
| 認証 | リクエストの送信者がだれかを確認すること | だれの求めかの確かめ |
| 認可 | 認証した利用者に、その操作を許可するかを判定すること | 許された操作かの確かめ |
| アクセス制御 | 利用者ごとに、読み書きできるデータの範囲を制限すること | 読み書きできる範囲 |
| セッション | ログインしてからログアウトするまでの状態。サーバーが管理する | ログインの状態 |
| 多要素認証(MFA) | パスワードに加えて、別の認証要素を求める認証。画面の文言では「2段階認証」と表示する | 2段階認証 |
| 認証要素 | 多要素認証で使う手段。本サイトでは認証アプリ(TOTP) | 2段階認証の手段 |
| アカウントロック | ログインの失敗が続いたアカウントで、一定時間ログインを受け付けないこと | ログインの制限 |
| レート制限 | 一定時間に受け付けるリクエストの数を制限すること | 回数の制限 |
| ボット対策 | 自動化されたプログラムによる不正な送信を防ぐ対策 | 迷惑な送信を減らす作り |
| 多層防御 | 1つの対策が破られても、別の対策で防ぐ設計。本サイトでは、サーバーの認可と RLS ポリシーの両方で確認する | 二重の守り |
| トークン | 推測できないランダムな値。メールのリンクの検証に使う | 乱数 |
| 有効期限付きリンク | トークンを含み、期限を過ぎると使えなくなるリンク | 期限のあるリンク |
| 入力バリデーション | 入力された値が、形式と範囲の条件を満たすかを検証すること | 入力の確かめ |
| CSRF | ほかのサイトから、ログイン中の利用者のリクエストを送らせる攻撃(クロスサイトリクエストフォージェリ) | ほかのサイトに置かれた仕掛け |
| XSS | ページに不正なスクリプトを埋め込む攻撃(クロスサイトスクリプティング) | 画面に入り込んだスクリプト |

| 用語 | 意味 | 以前の表記 |
|---|---|---|
| 本サイト | このリポジトリで開発するマーケットプレイスの全体 | サイト、アプリ |

| API キー | 外部サービスの API を呼び出すときに使う認証情報 | 鍵 |
| メール配信サービス | メールの送信を代行する外部サービス | メールを送るサービス |
| 通知 | 本サイトが利用者に送る連絡。購入者と生産者にはメールで送り、管理者には管理画面に表示する | 知らせ |
| 責務 | 構成要素やモジュールが担当する処理の範囲 | 受け持ち |

## 運用

| 用語 | 意味 | 以前の表記 |
|---|---|---|
| バックグラウンド処理 | 利用者の操作を起点にせず、システムが実行する処理。定期実行ジョブと、Webhook の処理を含む | 人の操作を待たずに動く処理 |
| 定期実行ジョブ | 決まった間隔で実行する処理(例: 期限切れのオーソリのキャンセル、照合) | 期限で動く処理 |
| Cron | 定期実行ジョブを、決まった時刻に起動する仕組み。本サイトでは Vercel Cron Jobs を使う | 期限で動く処理のきっかけ |
| 監視サービス | 処理の停止と失敗を検知して、保守担当者に通知する外部サービス | 監視のサービス |
| ハートビート | 処理が正常に終了したことを、監視サービスに定期的に送る信号。一定時間届かなければ、監視サービスがアラートを出す | 処理を終えた合図 |
| アラート | 障害の発生を、保守担当者に通知すること | 止まったときの知らせ |
| 保守担当者 | 本サイトの保守を担当する開発者 | 保守を担う開発者 |
| リストア | バックアップからデータを復元すること | 戻す |
| 目標復旧時点(RPO) | 障害のときに、どの時点のデータまで復元できるかの目標 | 失う間 |
| 目標復旧時間(RTO) | 障害から復旧するまでの時間の目標 | — |
