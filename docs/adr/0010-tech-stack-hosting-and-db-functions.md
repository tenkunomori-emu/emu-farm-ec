# ADR-0010: 技術の選定を今の要件で確かめ直し、本番も Vercel を使い、いくつかの行の書き込みをデータベースの関数で行う

- 日付: 2026-11-22
- ステータス: 採用

## 背景

- 作るものは、生産者が、それぞれ自分の商品を売るマーケットプレイスである。代金は、生産者ごとに直接入り、管理者は、アプリケーション手数料だけを受け取る。生産者が、だれの手も借りずに、自分で登録し、商品を出し、注文に対応し、代金を受け取れることが、技術を選ぶ基準である。
- ADR-0001([0001-tech-stack.md](0001-tech-stack.md))と ADR-0002([0002-hosting-and-ownership.md](0002-hosting-and-ownership.md))は、サイトの方向が決まる前に書いた。理由と前提が、確定した要件定義書([01-requirements.md](../01-requirements.md))と合わない。この ADR は、この2つを置き換える。技術の選定と置き場所は、この ADR だけを読めば分かるように書く。
- 基本設計書([02-basic-design.md](../02-basic-design.md))の「システム構成と技術の分担」は、置き場所で決まる性質(サーバーの処理の地域、受け取れる本文の大きさ、秘密の鍵の置き場所)を前提にしている。置き場所を決めないままでは、この章を確定できない。
- 注文を作ることと在庫を減らすことのように、片方だけが行われると記録がずれる書き込みがある(FR-050、FR-051、FR-052)。どこで1つにまとめるかを、決める必要がある。

## 検討した選択肢

### 本番の置き場所

| 選択肢 | 長所 | 短所 | 判断 |
|---|---|---|---|
| **本番も Vercel** | 開発、検証、本番が同じ置き場所になり、置き場所の違いで起きる不具合がない。基本設計書の決まり(サーバーの処理を東京の地域で動かす、4.5 MB を超える本文をサーバーの処理に通さない、秘密の鍵を環境変数に置く)を、そのまま使える | 無料のプランは、商用でない個人の利用に限られるため、有料のプランが要る(Vercel の公式ページ「Vercel Hobby Plan」) | **採用** |
| 本番の置き場所を、公開の前に比べて選ぶ | 運用の費用が、もっとも小さい置き場所を選べる | 置き場所が決まるまで、地域、本文の大きさの上限、期限で動く処理のきっかけを設計できない。本番の直前に置き場所を変えると、確かめ終えた動きを、もう一度確かめることになる | 採らない |

### いくつかの行を一度に変える書き込み

| 選択肢 | 確かめた事実 | 判断 |
|---|---|---|
| Next.js のサーバーから、行ごとに順に書く | Supabase のデータの API(PostgREST)は、求めごとに1つのトランザクションで動く。求めを2回に分けると、トランザクションも2つになり、1回目だけが行われて止まることがある | 採らない。在庫だけが減って注文がない、といった記録のずれが起きる |
| **データベースの関数にまとめ、Next.js のサーバーが1回呼ぶ** | 関数の呼び出しは1つの求めであり、1つのトランザクションで動く。関数の中の書き込みは、全部行われるか、全部行われないかのどちらかになる | **採用** |
| Next.js のサーバーからデータベースに直接つなぎ、アプリの側でトランザクションを書く | できる。ただし、データベースへのつなぎ方が、データの API と直接の接続の2つになり、サーバーの処理ごとに接続が増えるため、接続をまとめる仕組みが要る | 採らない。つなぎ方を1つにする |

## 決定

### 1. 技術の選定

Next.js(App Router)、TypeScript、Tailwind CSS、Supabase、Stripe を使う。

| 技術 | 今の要件での理由 |
|---|---|
| Next.js(App Router)、TypeScript | 商品の一覧、商品ページ、生産者のページを、サーバーで作って送れる(NFR-017、基本設計書の SYS-016)。お金の額の計算と、権限の確かめを、サーバーの処理に置ける(NFR-011、SYS-018、SYS-019)。1つのアプリの中を、モジュールに分けて作る(SYS-033〜SYS-042) |
| Tailwind CSS | 生産者と購入者の画面を、スマートフォンの幅で使えるように作る(NFR-018、NFR-019)。画面の幅ごとの見た目を、HTML の中で指定できる。見た目の決まりを1つの設定ファイルにまとめ、画面ごとにばらつかないようにできる |
| Supabase(PostgreSQL、認証、ファイルの保存) | 注文と在庫のように、同時に変える書き込みを、トランザクションで行える(この ADR の決定3)。行ごとに、読み書きできる人を限れる(SYS-018 の二重の守り)。写真を、ブラウザから直接送れ、見てよい人にだけ期限のある URL を出せる(SYS-025) |
| Stripe | 代金を、生産者の Stripe のアカウントで直接受け取り、管理者はアプリケーション手数料だけを受け取る(ADR-0004([0004-stripe-connect-direct-charges.md](0004-stripe-connect-direct-charges.md)))。注文のときに仮押さえし、生産者の操作で確定できる(ADR-0005([0005-stripe-account-holds-and-refunds.md](0005-stripe-account-holds-and-refunds.md)))。生産者の登録と不審請求の証拠を、サイトの中の部品で扱える(ADR-0009([0009-stripe-account-onboarding-and-spike-results.md](0009-stripe-account-onboarding-and-spike-results.md))) |

生産者が使う画面は、スマートフォンの幅で、注文の対応を終えられるように作る(NFR-019)。生産者は、Stripe のダッシュボードを使わず、Stripe に出す情報の登録も、サイトの中で行う(FR-007、FR-010)。

### 2. 本番の置き場所

- 本番も、Vercel を使う。開発、検証、本番を、同じ置き場所にする。
- Next.js のサーバーの処理は、データベースと同じ、東京の地域で動かす(SYS-010)。Vercel の初めの設定では、サーバーの処理は、アメリカの東海岸の地域で動く。
- ドメインは、この ADR では決めない。リリース・運用の工程で決める(開発の進め方([CONTRIBUTING.md](../../CONTRIBUTING.md#工程とゲート))の「工程とゲート」)。

### 3. いくつかの行を一度に変える書き込み

- 片方だけが行われると記録がずれる書き込みは、データベースの関数にまとめ、Next.js のサーバーは、その関数を1回呼ぶ(SYS-022)。2つのモジュールの書き込みを同時に行うときも、同じにする(SYS-045)。
- データベースの関数には、書き込みと、書き込みの条件の確かめ(在庫が数量以上あるか、状態が頼む前から変わっていないか)だけを置く。お金の額の計算、Stripe の呼び出し、知らせを送ることは、Next.js のサーバーに置く。
- データベースの関数は、マイグレーションのファイルで管理し、テストは、実装のコードと同じ PR に入れる(開発の進め方の「工程とゲート」)。

## 影響とリスク

- 処理の一部が、SQL の関数になる。TypeScript のコードと、書く場所が2つに分かれるため、関数に置くものを、決定3のとおりに限る。
- Stripe の呼び出しは、データベースのトランザクションに入れられない。Stripe に頼んだあと、結果を記録する前に処理が止まることがある。この場合の扱いは、基本設計書の SYS-028〜SYS-031(頼む前の確かめ、同じ鍵、結果が分からないときに Stripe で確かめる)で決めてある。
- ADR-0001 と ADR-0002 の決定のうち、この ADR に書いていないもの(ADR-0001 の「決定の前提」と「更新が必要な運用」、ADR-0002 の「ドメインの方針」と「引き渡し方針」)は、引き継がない。サイトの方向が決まる前に書いたためである。ドメインと引き渡しは、リリース・運用の工程で、そのときの要件で決める。ADR-0001 と ADR-0002 の本文は、決めた時点の記録として残し、ステータスを「置き換え済み」にする。
- Supabase のプロジェクトの地域が東京であることと、Vercel のサーバーの処理の地域の設定は、開発基盤の準備の工程で確かめる。
- 期限で動く処理のきっかけ(SYS-009)の仕組みは、この ADR では決めていない。基本設計書の「非機能と運用の方式」で決める。
