# ADR-0007: AI のレビューのモデル

- 日付: 2026-11-07
- ステータス: 採用

## 背景

- ADR-0003([0003-ai-review.md](0003-ai-review.md))では、モデル名を設定ファイルに書かず、標準のモデルを使うと決めた。
- PR #76 のレビューの実行の記録(2026-11-06)では、本体のモデルは claude-sonnet-5-5 だった。ほかに claude-haiku-5-5 も使われていた。
- 標準のモデルは、アカウントの種類と時期で変わる。そのため、レビューの質が、知らないうちに変わる。
- これからのレビューでは、要件定義書と設計書の中身を、ほかの文書と照らし合わせる。食い違いを見落とさないことを、使う量より優先する。

## 確認できた事実(公式ドキュメント、2026-11-07時点)

1. 別名 `opus` は、その時点の最新の Opus を指す。新しい版が出ると、設定ファイルを変えずに切り替わる。
2. 補助の処理(短いメッセージ、会話の要約、コマンドの処理)には、別名 `haiku` のモデルが使われる。レビューの判断とコメントを書くのは、本体のモデルである。
3. 補助の処理のモデルを変える環境変数には、版の付いた正式なモデル名を入れる必要がある。
4. Opus の利用量が一定を超えると Sonnet に戻る、という記述は、今の文書にはない。

## 決定

| 項目 | 方針 |
|---|---|
| 本体のモデル | 設定ファイルの `claude_args` に `--model opus` を書き、その時点の最新の Opus を使う。版の番号を含むモデル名は、設定ファイルに書かない |
| 補助の処理のモデル | 標準のまま(Haiku)にする。レビューの判断に関わらず、変えるには版の付いた名前を書く必要があるため |

この ADR は、ADR-0003 の「決定」の「モデル」の行を置き換える。ADR-0003 のほかの決定は、そのまま有効。

## 影響とリスク

- **使う量が増える**: 購読トークンを使うため、1回のレビューで使う量が、Sonnet より多い。上限(やり取りの回数と時間)は、ADR-0003 のまま。
- **版が、知らないうちに上がる**: 新しい Opus が出ると、レビューの本体も切り替わる。どの版で動いたかは、実行の記録の `"model"` で確かめられる。
- **購読のプランで Opus が使えない場合**: レビューが失敗する。PR #76 の実行が Sonnet だったため、トークンのプランの既定は Sonnet の可能性がある。
- **Sonnet に戻る場合**: 今の文書には書かれていないが、利用量などで本体が Sonnet に戻る動きがないかは、確認できていない。
- 上の2つは、設定ファイルを変えたあとの最初のレビューの実行の記録で確かめる。
