# ADR-0003: PR を AI がレビューする仕組みの導入

- 日付: 2026-10-28
- ステータス: 採用

## 背景

- PR を、書いた人とは別の目で確認する仕組みがほしい。
- 進め方のルール(文書の書き方、合意の記録、リンクなど)が増え、人の目だけでは、見落としが出やすい。
- マージするかどうかは、これまでどおり、作業する人が決める。主催者の合意が必要な変更は、合意をいただいてから進める。AI は、その判断を、置き換えない。

## 確認できた事実(公式ドキュメント、2026-10-28時点)

| 選択肢 | 確認できたこと |
|---|---|
| Claude Code の Code Review(Anthropic が運営するサービス) | 対象は、Team と Enterprise のプラン。組織の Owner が有効にする。レビューは、コメントを書くだけで、PR を承認も、止めもしない |
| Claude Code GitHub Actions(`claude-code-action`) | 設定ファイル(ワークフロー)を、リポジトリに置いて使う。認証は、Claude の API キー、または Pro、Max、Team、Enterprise の購読トークンでできる。設置には、リポジトリの管理者権限が必要 |
| GitHub Copilot code review | 有料の Copilot プランが対象で、Free プランは含まない。リポジトリのルートの AGENTS.md を、自動で読む。標準では、レビューは必要な承認の数に数えない |

Claude Code GitHub Actions について、ほかに確認できたこと。

1. 入れる GitHub App(Claude)の権限は、一部だけを許可することができない。権限には、コードや設定ファイルの書き込みを含む。
2. 購読トークンは、`claude setup-token` で作る。有効期間は1年で、発行した人の購読に結び付く。作ったときに画面に表示されるだけで、どこにも保存されない。
3. 公式ドキュメントに「シークレットを削除しても、そこに入れていた認証情報は有効のまま」と書かれている。トークンを無効にする方法は、ドキュメントに書かれていない。
4. 公開リポジトリでは、フォークからの PR に、シークレットが渡されない。そのため、レビューは、同じリポジトリのブランチからの PR だけで動く。
5. 動かす時点、使える操作、やり取りの回数と時間の上限は、設定ファイルで決められる。
6. 設定ファイル(`claude-review.yml`)を変える PR では、AI のレビューは書かれない。この仕組みは、安全のために、PR の設定ファイルと `main` の設定ファイルが同じ中身のときだけ動くため。このとき、実行の画面には「成功」と表示されるが、コメントは付かない。設定ファイルを最初に入れた PR #32 も、`main` にまだ設定ファイルがなかったので、レビューされなかった。

## 決定

Claude Code GitHub Actions で、PR を AI がレビューする仕組みを入れる。設定は [.github/workflows/claude-review.yml](../../.github/workflows/claude-review.yml) にある。

| 項目 | 方針 |
|---|---|
| 動かす時点 | PR を、下書きから「Ready for review」にしたときだけ。直したあとに、もう一度見てほしいときは、下書きに戻して、押し直す |
| AI にさせること | コメントを書くだけ。使える操作は、箇所への指摘、まとめのコメント、PR と Issue を読むことに絞る。ファイルの変更、コミット、承認、マージはさせない |
| ルールの読ませ方 | 作業の手引き([AGENTS.md](../../AGENTS.md#作業のルール))と、開発の進め方([CONTRIBUTING.md](../../CONTRIBUTING.md#ai-のレビュー))を読ませ、その内容に沿ってレビューさせる |
| 使う量 | やり取りの回数と、実行の時間に、上限を付ける。同じ PR で、同時に2つ動かさない |
| モデル | モデル名は、設定ファイルに書かない。標準のモデルを使う |
| 認証 | 購読トークンを、GitHub のシークレットに入れる。トークンは、チャット、Issue、PR、コミットに書かない |
| マージ | 作業する人が行う。主催者の合意が必要な変更は、合意をいただいてからマージする |

### 選ばなかった理由

- **Code Review(Anthropic が運営するサービス)**: 対象のプランが、Team と Enterprise に限られる。プランを前提にせずに、始められる方法を選んだ。
- **GitHub Copilot code review**: 有料の Copilot プランが必要。AGENTS.md を読めるので、**利用できなくなった場合の、代わりの候補として残す**。

## 影響とリスク

- **App の権限が広い**: コードの書き込みを含む権限を、持つことになる。次の3つで、動きを抑える。
  1. 設定ファイルで、使える操作を、コメントに絞る。
  2. `main` を保護する(PR が必要。ルールを迂回できる人は、いない)。
  3. マージは、作業する人が行う。
- **AI の指摘は、正しいとは限らない**: 試しの PR で、まだ確定していない版の名前を、確定した版のように書いた指摘が、1件あった。作業する人が、正本の文書で確かめてから、直す。
- **AI は、議事録を確認できない**: 議事録は、このリポジトリに置かないため。合意が合っているかは、作業する人が確かめる。
- **設定ファイルを直す PR では、動かない**: 上の確認できた事実の6による。実際に、直す PR で試してはいない。その場合は、作業する人が、自分で確かめる。
- **最初から「Ready for review」で出した PR では、動かない**: 動かす時点を、「下書きから Ready for review にしたとき」だけにしているため。その場合は、一度下書きに戻して、押し直す。
- **レビューの内容は、PR に残る**: このリポジトリは公開されているので、コメントは、誰でも見られる。
- **引き渡しのとき**: トークンは、発行した人のアカウントに結び付く。引き渡しのときに、引き継ぎ先のアカウントのトークンに、入れ替える。作り直したあとに、前のトークンが使えなくなるかは、確認できていない。
- **有効期間は1年**: 期限の前に、作り直して、シークレットを入れ替える。
