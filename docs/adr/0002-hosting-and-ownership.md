# ADR-0002: ホスティング・ドメイン・引き渡し方針

- 日付: 2026-10-23
- ステータス: 提案(ホスティングの最終選定は、引き渡しの前に行う)

## 背景

- 成果物は、運営者(牧場側)に引き渡し、その後チーム開発で更新する。
- 運用にかかる費用は、小さく保ちたい。

## 確認できた事実(Vercel公式ドキュメント、2026-10-23時点)

1. **Hobby(無料)は、非商用の個人利用のみ**。「商業利用」は、デプロイが関与する誰かの金銭的利益を目的とする場合と定義され、コードを書く有給の従業員やコンサルタントも含む。寄付を募ることは、商業利用に当たらない。
2. 商業利用には、ProまたはEnterpriseが必要。
3. Hobbyでは、GitHubの組織(Organization)が持つ非公開リポジトリから、デプロイできない。公開リポジトリにするか、Proにする必要がある。
4. Proは、月額20米ドル。開発・デプロイできる1席と、月20米ドル分の利用クレジットを含む。追加の席は、1人あたり月20米ドル。閲覧専用(Viewer)は無料。
5. 独自ドメインは、Vercelで購入でき、他社で買ったドメインを使うこともできる。
6. プロジェクトは、チーム間で、停止時間なしに移管できる(移管元のOwnerと、移管先のメンバーが必要。移管先に、支払い方法の登録が必要)。

## 解釈(要確認)

- 商品を売るサイトは、運営者の金銭的利益を目的とするため、**公開して運用する時点で、商業利用に当たる可能性が高い**。
- 紹介だけの段階が商業利用に当たるかは、グレー。判断は、Vercelのサポートに確認する。
- これらは、公式ドキュメントの読み取りであり、最終判断ではない。

## 決定(提案)

| 段階 | 方針 | 理由 |
|---|---|---|
| 開発・試作 | 開発者のVercel Proチームの中の、**別プロジェクト**として運用する。URLは `〇〇.vercel.app` | 追加費用なしで、商業利用の条件を満たす。他のプロジェクトとは、設定とデータを分ける |
| 引き渡し前 | **置き場所を比較し、運用費用がもっとも小さくなる方法を選ぶ**(Vercel Pro、他のホスティング、など) | 運用にかかる費用を、小さく保つ |
| 引き渡し | 選んだ置き場所を、運営者の名義・管理下へ移す | 運営の責任の所在を、一致させる |

- 他のホスティングの利用条件・料金は、**まだ調べていない**。比較の前に、公式の情報で確認する。
- 引き渡しは、**各段階の承認と、運営の準備が整ってから**行う。

## ドメインの方針

- 取得は、試作で合意を得てからでよい。
- ただし、次の場合は、**取得を前倒しする**。
  - QRコード・チラシなど、印刷物にURLを載せる前
  - メール配信や、独自のメールアドレスを使い始める前
  - Stripeの本番利用の申請前
- **名義は、運営者(牧場側)にする**ことを原則とする。開発者個人の名義で取ると、引き渡しのときに移管の手間と、トラブルの元になる。
- DNSの管理場所は、**1か所に決めてから**、メール等の設定をする。
- 希望のドメイン名と、`.jp`が購入先で扱えるかは、要確認。

## 引き渡し方針

1. 成果物(コード、設計書、各種アカウント)の、**権利と引き継ぎの範囲を、書面で合意**する。
2. **成果物の公開の範囲**を、明文化する(公開するもの、公開しないもの、写真・ロゴの扱い)。
3. 各種アカウント(GitHub、ホスティング、Supabase、Stripe、ドメイン)は、運用開始までに、運営者の名義・管理下へ移す手順を決める。
4. 引き渡し後の、保守の担当と、費用の負担を決める。

合意書の文案は、専門家に確認する(法的助言ではない)。

## 影響とリスク

- 無料のまま、公開して運用すると、規約違反でサービスが止まるおそれがある。
- 開発者のチームに置いたまま運用を続けると、運用の責任が、開発者に残る。引き渡しの手順を、先に決めておく。
