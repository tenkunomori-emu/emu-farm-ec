# ADR-0006: 購入の形(カートを作らない。1回の注文は1つの商品)

- 日付: 2026-11-04
- ステータス: 採用

## 背景

- ADR-0004([0004-stripe-connect-direct-charges.md](0004-stripe-connect-direct-charges.md))で、支払いを Stripe Connect のダイレクト支払いにすると決めた。1回の支払いの代金は、1人の生産者のアカウントに入る。管理者は代金を預からない。
- ADR-0005([0005-stripe-account-holds-and-refunds.md](0005-stripe-account-holds-and-refunds.md))で、注文のときに代金を仮押さえし、生産者が「発送する」を押したときに確定すると決めた。確定は原則1回だけで、一部だけ確定すると、残りの仮押さえは解かれる。
- 管理者は、代金を預からず、返金や不審請求で損をしない方針である(議事録_2026_1102)。
- ADR-0004 では、複数の生産者の商品を買う場合は、生産者ごとに支払いを分けるとしていた。カートの有無と、1回の注文で荷物が2つ以上になる場合の支払いと送料の扱いは、決めていなかった。

## 検討した選択肢

| 選択肢 | 長所 | 短所 | 判断 |
|---|---|---|---|
| カートで複数の生産者の商品を買い、生産者ごとに支払いを分ける | 購入者が1回の手続きで買える | 1回の手続きで、生産者ごとの支払いを複数作る。1人の生産者の支払いだけが失敗したときの扱いが要る。1回のカード入力で複数の生産者のアカウントに支払いを作る仕組みは、確かめていない | 採らない |
| 管理者が代金を受け取って、生産者に分ける(支払いと送金別方式) | 1回の支払いで、複数の生産者の商品を買える | 返金、不審請求、Stripe の手数料が、管理者の残高から出る。管理者が代金を預からず損をしない方針と合わない | 採らない |
| カートは、同じ生産者の商品だけにする | 同じ生産者の商品を、1つの箱と1回の送料で買える | 複数の商品をまとめたときの箱の大きさと送料の決め方が要る | 採らない |
| **カートを作らず、1回の注文は1つの商品と、その数量にする** | 購入者が迷わない。カートに入れたままの放置が起きない。1回の注文の支払いは1つ、発送は1回で、確定、返金、不審請求が1つの注文の中で完結する | 異なる商品を一緒に買うと、注文と送料が2回になる | **採用** |

## 決定

1. カートは作らない。購入者は、商品ページから、すぐに購入手続きへ進む(要件定義書 v1.6([01-requirements.md](../01-requirements.md))の F-10)。
2. 1回の注文は、1人の生産者の1つの商品と、その数量とする。複数の生産者の商品を1回で買うことはできない。1回の注文の支払いは1つ、発送は1回とする。ADR-0004 の「複数の生産者の商品は、生産者ごとに支払いを分ける」は、この決定に置き換わる。
3. 異なる商品を一緒に買いたい購入者には、生産者がセット商品を並べて応える。セット商品は、普通の商品として登録する。
4. 生産者は、商品ごとにヤマト運輸の箱のサイズを1つ登録し、1回の注文で買える数量の上限を、その箱に入る数とする(F-14)。1回の注文は箱1つになる。送料は、その箱のサイズと運賃表で決まり、商品ページに、地域ごとの送料と、送料込みの合計を表示する(F-10、F-12)。
5. 管理者の負担の値引き(クーポン、送料の割引、ポイント)は、フェーズ2では作らない。代金は生産者に直接入るため、管理者の負担で値引きすると、生産者の売上が減る。値引きは、生産者が自分の商品の価格で行う。

## 影響とリスク

- 異なる商品を一緒に買う購入者は、注文と送料が2回になる。生産者がセット商品を並べることで補う。
- 将来カートを足す場合: 注文は生産者1人の単位で、明細(order_items)のテーブルを残すので、1つの注文に複数の商品を入れられる。お金のテーブル(注文、返金、不審請求)は作り直さない。複数の商品をまとめたときの箱の大きさと送料の決め方と、箱が2つ以上になる場合の荷物のテーブルを、そのときに足す。
- 将来、複数の生産者の商品を1回で買う形を足す場合: ダイレクト支払いのまま、生産者ごとに注文と支払いを作り、それらをまとめるテーブルを足す。お金のテーブルは作り直さない。1回のカード入力で複数の生産者のアカウントに支払いを作る仕組みと、1つだけ失敗したときの扱いを、テスト環境で確かめる必要がある。購入者のカードの明細には、生産者ごとに別々の請求が並ぶ。
- 1つの支払いを何回かに分けて確定する機能(multicapture)は、Stripe の IC+ の料金体系で使える機能で、このサイトで使えるかは確かめていない。この決定は、この機能を使わない前提である。
