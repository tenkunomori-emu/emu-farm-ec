# ADR-0008: MVP では、JCB、ダイナースクラブ、ディスカバーを受け付けない

- 日付: 2026-11-19
- ステータス: 採用

## 背景

- 議事録_2026_1104 で、支払い方法に JCB(ダイナースクラブ、ディスカバーを含む)を入れると決めた。ADR-0005([0005-stripe-account-holds-and-refunds.md](0005-stripe-account-holds-and-refunds.md))では、JCB は生産者ごとの設定で、管理者が API で生産者ごとに有効にし、JCB の審査が終わるまで、その生産者は JCB を使えない、としていた(2026-11-04 のテスト環境の結果)。
- 2026-11-18 と 2026-11-19 に、Stripe の公式ページとテスト環境で確かめ直した(確認事項_2026_1118、確認事項_2026_1119)。今の仕組みは次のとおり。
  - 公式ページには、日本の生産者のアカウントは、有効になると、JCB、ダイナースクラブ、ディスカバーをすぐに受け付けられる、と書かれている。テスト環境では、プラットフォームは jcb_payments を申し込めなかった。受け付けが始まるかどうかを、プラットフォームは決められない。
  - JCB は、生産者のアカウントごとに自動で審査し、拒否したり、追加の情報を求めたりすることがある。拒否は最終の決定である。
  - 拒否されたときと追加の情報を求められたときは、それより前の JCB の支払いが自動で返金される。承認の決定は、あとで変わることがある。
- 自動の返金は、サイトのだれも操作していないのに代金が戻る出来事である。審査の結果が出る前に代金を確定して商品を送った注文で起きると、その生産者は商品と送料の分を損する。

## 検討した選択肢

| 選択肢 | 長所 | 短所 | 判断 |
|---|---|---|---|
| Stripe の自動の受け付けと審査のまま使い、仕組みを前もって生産者に伝える | 合意した支払い方法のままで使える | 自動の返金を受けたあとの注文の扱い(注文の取り消し、生産者への知らせ、返金の申し出と返金の依頼、返金の記録)に、要件が5つ要る。それでも、発送のあとに返金されたときの生産者の損は防げない | 採らない |
| 審査の結果が出るまで、システムがその生産者の JCB の支払いを止める | 審査の結果が出る前の支払いがなく、自動の返金がほとんど起きない | 審査中の jcb_payments の状態の値が公式ページに書かれておらず、審査中と承認済みを見分けられるか分からない | MVP では採らない。あとから受け付けるときの候補とする |
| **MVP では、JCB、ダイナースクラブ、ディスカバーを受け付けない** | 自動の返金が起きず、代金が動くのは、サイトでの操作と不審請求だけになる | 合意した支払い方法から外れる。JCB、ダイナースクラブ、ディスカバーのカードしか持たない購入者は買えない | **採用** |

## 決定

1. MVP では、JCB、ダイナースクラブ、ディスカバーのカードの支払いを受け付けない。Apple Pay、Google Pay、Link に登録されたカードも含む(要件定義書([01-requirements.md](../01-requirements.md))の FR-225)。受け付ける支払い方法は、カード(Visa、Mastercard、American Express)、Apple Pay、Google Pay、Link の4つとする(FR-044)。
2. 管理者が生産者ごとに JCB を有効にする操作と、審査が終わるまで受け付けない仕組みは作らない(FR-016 と FR-017 は削除した)。ADR-0005 の「5. 決済手段の設定」の JCB の扱いは、この決定に置き換わる。
3. 支払いは、サーバーでカードのブランドを確かめ、JCB、ダイナースクラブ、ディスカバーなら確定しないことで止める。画面でも、これらのカードを使えないようにする。作り方は、基本設計で決める。
4. JCB、ダイナースクラブ、ディスカバーの受け付けは、MVP の後のフェーズ(リリース3)で扱う(要件定義書の「1.4 MVP の後のフェーズ」)。受け付けるときは、止めている処理を外し、審査の結果の受け取りと、自動の返金を受けたあとの注文の扱いを入れる。

## 影響とリスク

- JCB、ダイナースクラブ、ディスカバーのカードしか持たない購入者は、MVP では買えない。
- 支払いの止め方は、公式ページの記述で確かめたもので、テスト環境では確かめていない。画面では Payment Element のカードのブランドの絞り込みを、サーバーでは支払いを確定する前のカードのブランドの確かめを使う。Link で払ったときにカードのブランドを確かめられるかは、公式ページに書かれていない。基本設計で確かめ、確かめられないときは、Link の扱いを見直す。
- 画面のカードのブランドの絞り込みでは、JCB、ダイナースクラブ、ディスカバーと同じ値に UnionPay と Elo が入っており、あわせて止まる。受け付けるカードは Visa、Mastercard、American Express のため、影響はない。
- 決済手段の設定で JCB を無効にする方法は、採らない。テスト環境では、無効の状態でも JCB のカードの仮押さえが通り、本番で止まるかを確かめられないためである。
- テスト環境では、Accounts v1 で生産者のアカウントを作れなかった(v1_accounts_create_blocked)。ADR-0005 の「生産者のアカウントの設定」は Accounts v1 の項目で書かれており、基本設計で Accounts v2 の項目に直す。
- あとから受け付けるときは、審査で承認された生産者にだけ受け付けを開ける形が候補になる。審査中と承認済みを見分けられるかは、確かめていない。
