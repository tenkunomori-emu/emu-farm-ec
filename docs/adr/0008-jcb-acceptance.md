# ADR-0008: JCB の受け付けは、Stripe の自動の受け付けと審査のまま使う

- 日付: 2026-11-18
- ステータス: 採用

## 背景

- 議事録_2026_1104 で、支払い方法に JCB(ダイナースクラブ、ディスカバーを含む)を入れると決めた。ADR-0005([0005-stripe-account-holds-and-refunds.md](0005-stripe-account-holds-and-refunds.md))では、JCB は生産者ごとの設定で、管理者が API で生産者ごとに有効にし、JCB の審査が終わるまで、その生産者は JCB を使えない、としていた(2026-11-04 のテスト環境の結果)。
- 2026-11-18 に、Stripe の公式ページとテスト環境で確かめ直した(確認事項_2026_1118)。今の仕組みは次のとおり。
  - 日本の生産者のアカウントは、有効になると、JCB、ダイナースクラブ、ディスカバーをすぐに受け付けられる。プラットフォームは jcb_payments を申し込めない(テスト環境で、申し込むとエラーになった)。
  - JCB は、生産者のアカウントごとに自動で審査し、拒否したり、追加の情報を求めたりすることがある。拒否は最終の決定である。
  - 拒否されたときと追加の情報を求められたときは、それより前の JCB の支払いが自動で返金される。追加の情報を求められたときは、承認されるまで新しい JCB の支払いが止まる。承認の決定は、あとで変わることがある。
  - 審査の結果は capability.updated の Webhook で、追加の情報の要求はメールで、プラットフォームに知らされる。
- 審査の結果が出る前に代金を確定して商品を送った注文が自動で返金されると、その生産者は商品と送料の分を損する。

## 検討した選択肢

| 選択肢 | 長所 | 短所 | 判断 |
|---|---|---|---|
| MVP では JCB(ダイナースクラブ、ディスカバーを含む)を受け付けず、システムがカードのブランドを見て止める | 自動の返金が起きる支払いがなくなる | 議事録_2026_1104 で合意した支払い方法から外れる。JCB のカードの購入者は、ほかの支払い方法を選ぶ必要がある。止め方は確かめていない | 採らない |
| 審査の結果が出るまで、システムがその生産者の JCB の支払いを止める | 自動の返金で生産者が損をしない | 審査中の jcb_payments の状態の値が公式ページに書かれておらず、審査中と承認済みを見分けられるか分からない | 採らない |
| **Stripe の自動の受け付けと審査のまま使い、仕組みを前もって生産者に伝える** | 合意した支払い方法のままで、システムの作りが増えない。最初の生産者は限られており、伝えることで足りる | 審査の結果が出る前に送った注文が自動で返金されると、生産者が損をする | **採用** |

## 決定

1. JCB(ダイナースクラブ、ディスカバーを含む)は、Stripe の自動の受け付けと審査のまま使う。管理者が生産者ごとに JCB を有効にする操作と、審査が終わるまで受け付けない仕組みは作らない(要件定義書([01-requirements.md](../01-requirements.md))の FR-016、FR-017 を削除し、FR-044 を直した)。ADR-0005 の「5. 決済手段の設定」の JCB の扱いは、この決定に置き換わる。
2. 生産者が生産者向けの利用規約に同意するとき、システムは、審査で拒否されたときや追加の情報を求められたときに、それより前の JCB の支払いが発送のあとでも自動で返金されることを示す(FR-225)。
3. 自動の返金のように、生産者と管理者がサイトで行ったものでない、Stripe の側で行われた返金は、注文の記録に反映し(FR-095)、返金した注文として扱い、返金した人を Stripe の側の返金として記録する(FR-226)。「発送を知らせる」が押される前の注文は取り消して「発送を知らせる」を押せなくし(FR-101)、購入者に返金の額を知らせる(FR-126)。生産者には、返金されたことと額を、「発送を知らせる」が押される前の注文では商品を発送しないことも、自動で知らせる(FR-227)。返金した注文になると、閉じていない返金の申し出と、取り下げられていない返金の依頼を閉じ、答える期限で生産者が停止されないようにする(FR-228)。
4. 審査で追加の情報を求められたときは、Stripe がプラットフォームに知らせるため、管理者が生産者に伝える。手順は、操作手順書に書く。
5. 生産者ごとの審査の結果をシステムで受け取ることと、承認のあとに決定が変わったときの扱いは、MVP の後のフェーズ(リリース3)で作る(要件定義書の「1.4 MVP の後のフェーズ」)。

## 影響とリスク

- 審査の結果が出る前に代金を確定して送った注文が自動で返金されると、その生産者が商品と送料の分を損する。前もって伝えることで、生産者が知らないまま損をすることは防げるが、損そのものは防げない。商品を運送会社に渡す前に返金されたときは、生産者への知らせ(FR-227)で発送を止められる。
- 審査で拒否された生産者の商品は、JCB(ダイナースクラブ、ディスカバーを含む)で払えなくなり、注文のときの仮押さえが通らず、注文は成立しないと考えられる(公式ページの「新しい JCB の支払いの受け付けが止まる」からの判断で、テスト環境では確かめていない)。購入者は、ほかの支払い方法を選べる。
- テスト環境では、作った時点の生産者のアカウントで、jcb_payments は申し込まれていなかった(null)。アカウントが有効になったあとに JCB を受け付けられるようになるかは、確かめていない。基本設計で、生産者のアカウントの作り方を決めるときに確かめる。受け付けられないときは、FR-044 とこの決定を見直す。
- テスト環境では、Accounts v1 で生産者のアカウントを作れなかった(v1_accounts_create_blocked)。ADR-0005 の「生産者のアカウントの設定」は Accounts v1 の項目で書かれており、基本設計で Accounts v2 の項目に直す。
- 審査中の jcb_payments の状態の値は、公式ページに書かれておらず、確かめていない。リリース3で審査の結果を受け取るときに確かめる。
