## 1. 目的

過疎が進む地域に、エミューを起点とした新しい産業と交流を生み、次の世代へつなぐ。
そのために、牧場の取り組みと商品を**全国の人に知ってもらい、買い・訪れ・応援してもらえる入口**を作る。

## 2. 現状と課題

| 項目 | 現状 | 出典/備考 |
|---|---|---|
| Webサイト | なし | 主催者へのヒアリング |
| 商品 | エミューオイル、エミュー石鹸、イベントで販売される現地の農作物(クッキー等はCAMPFIREの返礼品) | 主催者へのヒアリング/CAMPFIRE |
| 課題 | **商品や牧場が、まだ広く知られていない** | 主催者へのヒアリング |
| 報道 | 地元の新聞で、牧場の開設とヒナの誕生が紹介されている | 中日新聞(2025/4/1ほか) |
| 取り組み | CAMPFIREのプロジェクトを実施(2026/5/30〜8/17) | CAMPFIREのプロジェクトページ(2026年10月23日閲覧) |
| 問い合わせ | イベントについての問い合わせが来ている | 主催者へのヒアリング |
| 現在の販売 | 自前のサイトがないため、他の販売サイトで販売している | 主催者へのヒアリング |
| 販売体制 | 要確認(梱包・発送・問い合わせ対応の担当者) | 未確認 |

**結論**: 課題は「商品」ではなく「認知と、関心を持った人との接点づくり」。
サイトの最初の役割は、販売より先に**見つけてもらい、連絡先を残してもらうこと**。

## 3. 目標(KPI案・要合意)

数値は主催者との合意で確定する。ここでは測る項目だけを定義する。

- 月間訪問者数、流入元(検索、SNS、新聞・イベントのQR 等)
- メール/LINE登録者数
- イベント・見学の問い合わせ件数
- 商品ページ閲覧→購入の転換率(フェーズ2以降)
- リピート購入・応援会員数(フェーズ3以降)

## 4. スコープとフェーズ

### フェーズ1: 知ってもらう・つながる(最優先)
- 牧場紹介(物語、地域の状況、エミュー)
- イベント情報(「ぷぶふの日」等)
- 問い合わせフォーム(イベント・見学・取材・協賛)
- メール/LINE登録
- 商品紹介ページ(購入は、現在販売している他の販売サイトへ誘導する)
- 管理画面の一部(ログイン、お知らせ・イベントの編集)
- アクセス解析
- 生産者の情報の登録(最初は牧場の1件)
- プライバシーポリシー(**フェーズ1で必須**。問い合わせとメール/LINE登録で個人情報を受け取るため、公開の時点で利用目的を示す)
- 特定商取引法に基づく表記の雛形(フェーズ2で必須)

### フェーズ2: 買える
- 商品、カート、決済(Stripe Connect のダイレクト支払い。代金は生産者に直接入る)、在庫、注文管理
- 注文ごとのメッセージ(写真を付けられ、履歴が残る)、返金の申し出と返金
- ゲスト購入(会員登録なしで買える)、送料の早期表示。送料は、運賃表から自動で計算し、運賃表を購入者向けのページで公開する
- 配送設定、注文メール
- 管理画面の拡張(商品・在庫・注文)
- 特定商取引法表記、薬機法・食品表示への対応(下記「[法務・コンプライアンス](#8-法務コンプライアンス確認チェックリスト)」)

### フェーズ3: 参加する・続ける
- 体験・見学の予約
- 応援会員(会員ページ、成長日記、月額課金)
- ※出資や利益分配の形にしない。「応援＋特典」の設計に留め、設計前に専門家へ確認する

### 将来(フェーズ4): 静岡県の生産者が参加する
- 静岡県の生産者が出品できる産直サイトにする(マーケットプレイス化。産直サイトの「ポケットマルシェ」のような形を目標とする)
- 規模が大きくなってからでよい。**ただしデータ設計はフェーズ1から対応しておく**([02-data-design.md](02-data-design.md))
- 生産者ごとの出品・注文の管理(F-30)を加える。決済の仕組み(Stripe Connect)は、フェーズ2から使う

### スコープ外(当面)
- 自前のポイント制度、モバイルアプリ、海外向け配送、多言語

### 認知のための施策(サイト外を含む)

サイトを作るだけでは、見つけてもらえない。次の施策を、サイトの機能と合わせて進める。

| 施策 | 内容 | 対応する要件 |
|---|---|---|
| 検索で見つけてもらう | 「エミューオイル」「静岡」などで調べた人に届くページをつくる | F-05、NF-02 |
| SNS・動画での発信 | Instagram・YouTubeなどで、エミューの成長を発信する | F-06 |
| 報道・応援の紹介 | 新聞記事や、自治体・応援してくださった方のコメントを紹介する(掲載の許可を得たもの)。過去の応援者へのご報告 | F-01、F-06 |
| イベント会場からの導線 | 会場のQRコードから、サイトに来て、メール/LINEの登録ができる | F-04、NF-04 |
| ふるさと納税の返礼品 | 森町の返礼品への登録の可能性(町への確認が必要) | 未確定([第10章](#10-未確定事項主催者に確認中)の RQ-10(森町のふるさと納税の返礼品への登録の可否)) |
| 協賛のご案内 | 協賛をご検討の企業・店舗向けの案内ページ | F-08 |

## 5. ユーザー像

| ユーザー | 目的 | 想定する困りごと |
|---|---|---|
| 初めて知る人(検索・SNS・イベント経由) | 何の牧場か知りたい、商品を試したい | 信頼できる主催者か分からない |
| 地域・取り組みを応援したい人 | 応援のしかたを知りたい | 何をすれば応援になるか分からない |
| イベント参加者 | 日程・行き方を知りたい | 情報が点在している |
| 協賛を検討する企業・店舗 | 協賛の内容・効果を知りたい | 窓口が分からない |
| 運営メンバー(非エンジニア含む) | 商品・イベント・注文を自分で更新したい | コードを触れない |

### 5.1 役割と権限

サイトを使う人を、次の4つの役割に分ける。権限は、アプリのコードだけでなく、データベースの行レベルセキュリティ(RLS)でも守る(NF-06(権限))。具体的なテーブルごとの権限は、基本設計で決める。

| 役割 | 誰か | ログイン | できること | 使い始める段階 |
|---|---|---|---|---|
| 来訪者 | サイトを見る人、購入者 | 不要 | 公開ページの閲覧、問い合わせ、メール/LINE登録。フェーズ2からは、ゲスト購入、自分の注文の確認、注文ごとのメッセージ、返金の申し出 | フェーズ1 |
| 運営メンバー | サイトの運営を担う人(非エンジニアを含む) | 必要 | お知らせ・イベントの編集、問い合わせの確認 | フェーズ1 |
| 管理者 | サイト全体の責任者。引き渡し前は開発者、引き渡し後は主催者 | 必要 | 運営メンバーができることのすべて。加えて、メンバーの招待・削除、役割の変更、サイト全体の設定、生産者の情報の登録(F-32)、送料の運賃表の管理(F-12)、生産者がメッセージで依頼したときの返金(依頼どおりの区分と額。F-16)、生産者ごとのアプリケーション手数料率の設定(F-31) | フェーズ1 |
| 生産者 | 商品を出品し、代金を受け取る事業者。農産物などを生産する人のほか、自ら加工・開発した商品(例: エミューオイル、石けん)を販売する人も含む。**牧場は生産者の1件目**とし、将来、静岡県の生産者が加わる | 必要 | 自分の商品・在庫・出荷・注文だけを扱う(注文ごとのメッセージ、返金を含む)。銀行口座と本人確認の情報の更新、不審請求への対応も行う。他の生産者のデータは見えない | フェーズ2(牧場)、フェーズ4(他の生産者) |

- 1人が複数の役割を持てる(例: 牧場の方が、運営メンバーと生産者を兼ねる)。
- 応援会員(フェーズ3)は、役割ではなく来訪者の会員登録として扱う。扱いはフェーズ3の設計で決める。
- F-32(生産者の情報の登録)は、フェーズ1では管理者が管理画面で行う。生産者の役割でログインして使うのは、フェーズ2からとする。

## 6. 機能要件(概要)

表は ID の順に並べている。フェーズの順ではない(ID は変えない決まりのため)。

| ID | 機能 | フェーズ | 優先度 |
|---|---|---|---|
| F-01 | 牧場・取り組み紹介ページ | 1 | 必須 |
| F-02 | イベント一覧・詳細 | 1 | 必須 |
| F-03 | 問い合わせフォーム(種別: イベント/見学/取材/協賛/商品) | 1 | 必須 |
| F-04 | メール/LINE登録 | 1 | 必須 |
| F-05 | 商品一覧・詳細(SEOを考慮)。フェーズ1では、購入ボタンから、現在販売している他の販売サイトへ移動する | 1 | 必須 |
| F-06 | お知らせ・成長日記の更新(非エンジニアが更新可能) | 1 | 高 |
| F-07 | アクセス解析 | 1 | 必須 |
| F-08 | 協賛・応援のご案内ページ(企業・店舗向け) | 1 | 中 |
| F-09 | 管理画面の一部: ログイン、お知らせ・イベントの編集、問い合わせの確認、生産者の情報の登録(F-32)(第5.1節の役割で操作を分ける) | 1 | 必須 |
| F-10 | カート・決済(フェーズ2の支払い方法はカードだけ。コンビニ払いは、手動の確定に対応しないため使わない)。**ゲスト購入**(会員登録なしで買える)に対応し、**送料を商品ページとカートで表示**する(購入手続きの最後まで送料が分からない状態にしない)。商品ページとカートでは、送り先の都道府県を選ぶと、送料の目安を表示する。購入手続きで住所を入力したら、確定した送料を表示し、代金に加える。購入者は、F-12 で公開する運賃表のページで内訳を確認できる。運賃を自分で計算する必要はない。注文のときは代金を仮押さえし、生産者が「発送する」を押したときに確定する。仮押さえの有効期間は通常7日間で、延ばせない。7日以内に「発送する」が押されない注文は、自動で取り消し、在庫を戻し、生産者と購入者に知らせる。購入手続きの画面(注文するとき)に、「注文のときは仮押さえで、発送のときに代金が確定する」ことを表示する | 2 | 必須 |
| F-11 | 在庫管理 | 2 | 必須 |
| F-12 | 注文管理・発送ステータス。送料の運賃表(大きさ・重さ × 発送元と送り先)の管理と、購入者向けのページでの公開を含み、運送会社の料金の変更に合わせて、管理画面から直せる。生産者が「発送する」を押すと、その場で代金を確定し、成功したら「発送してください」、失敗したら「発送しないでください」と表示する。注文ごとに、発送の期限(仮押さえの期限)を表示する。注文から7日を超えて発送する商品(予約販売など)は売れないことを、生産者が「発送する」を押す画面に必ず記載する | 2 | 必須 |
| F-13 | 注文確認メール。ゲスト購入の人のため、自分の注文の画面へのリンクを入れる。リンクは、他の人が推測できないものにする | 2 | 必須 |
| F-14 | 管理画面の拡張: 商品・在庫・注文の管理(F-09(管理画面の一部)の上に追加する)。注文から7日を超えて発送する商品(予約販売など)は売れないことを、生産者が商品を登録する画面に必ず記載する | 2 | 必須 |
| F-15 | 注文ごとのメッセージ(購入者と生産者のやり取り。写真を付けられ、履歴が残る)。ゲスト購入の人は、注文確認メール(F-13)のリンクから、自分の注文の画面を開いて使う | 2 | 必須 |
| F-16 | 返金の機能(購入者の「返金の申し出」ボタン、生産者の返金ボタン、申し出と返金の通知のメール)。申し出ても、返金やキャンセルは自動では行われない。ゲスト購入の人も、注文確認メール(F-13)のリンクから開く注文の画面で、申し出る。発送前のキャンセルは、生産者が了承したら、仮押さえを取り消す。決済手数料もアプリケーション手数料もかからない。生産者が発送できないとき(売り切れ、収穫できないなど)は、購入者にメールで知らせ、仮押さえを取り消す。申し出のボタンは、「発送する」を押した日から2週間で使えなくなる。生産者の返金ボタンと管理者の返金ボタンは、2週間のあとも使える。発送後の購入者の都合の返金額は、支払いの総額から、決済手数料(Stripe が注文ごとに記録した実際の額)、アプリケーション手数料、送料を引いた額として、画面で自動計算する。計算した額が0円以下のときは、返金額を0円とする。生産者の都合(不具合など)の返金は、全額または一部とし、金額は返金をする人が入力する。不具合のときは送料も返金する。決済手数料とアプリケーション手数料は、生産者が持つ。返金の区分は、購入者が選んだ理由を最初の値とし、返金をする人が変更できる。管理者が返金の操作をするのは、生産者がメッセージで依頼したときだけとし、管理者は依頼された区分と額のとおりに返金する。管理者は、返金の額を判断しない。不具合の申し出には、写真の添付を必須にする。返金は、サイトの管理画面から行い、Stripe の画面からは行わない。Stripe からの返金の通知を受け取り、注文の記録に反映する。不審請求(チャージバック)が起きたときは、生産者に通知し、サイトの中の画面で、生産者が自分で対応(証拠の提出など)できる。管理者は判断しない | 2 | 必須 |
| F-20 | 体験・見学予約 | 3 | 高 |
| F-21 | 応援会員(会員ページ、月額課金) | 3 | 高 |
| F-30 | 生産者管理・生産者ごとの出品/注文管理(生産者の情報の登録は、F-32 でフェーズ1へ先取りする) | 4 | 将来 |
| F-31 | 売上の分配(Stripe Connect のダイレクト支払い。代金は生産者に直接入り、管理者は預からない)。決済のたびに、管理者がアプリケーション手数料を受け取る。率は商品代金(送料を除く)の15%を基本とし、生産者ごとに設定で変えられる。率を設定できるのは管理者だけで、生産者は変更できない。牧場の率は0%。円未満は切り捨てる。注文ごとに、適用した率と額を記録する。生産者は、決済手数料とアプリケーション手数料を負担する。購入者の都合の返金では、F-16 のとおり、購入者の返金額から引く。返金しても、アプリケーション手数料は返さない。生産者は、銀行口座と本人確認の情報を、サイトの中の画面で登録・更新できる(生産者には Stripe のダッシュボードを使わせない)。生産者への入金の時期は、Stripe の標準とする | 2 | 必須 |
| F-32 | 生産者の情報の登録(最初は牧場の1件)。Stripe の生産者のアカウントとのつながりは、フェーズ2の F-31 で作る | 1 | 必須 |

## 7. 非機能要件

方針: 見た目を重視し、かつ**壊れず、速く、安全である**ことを品質の中心に置く。表示性能は、Googleが「良好」とする基準(Core Web Vitals: LCP 2.5秒以内、INP 200ミリ秒以下、CLS 0.1以下。75パーセンタイル)を基準とする。

| ID | 分類 | 要件 | 目標(案) | 確認方法 |
|---|---|---|---|---|
| NF-01 | 表示速度 | モバイルでの表示が速い | Lighthouse(モバイル)Performance 90以上 | CIで計測し、結果を記録 |
| NF-02 | SEO | 商品・物語ページが検索に載りやすい | Lighthouse SEO 95以上。構造化データ(商品、イベント)、サイトマップ | CI、Search Console |
| NF-03 | アクセシビリティ | 文字の読みやすさ、キーボード操作 | Lighthouse Accessibility 90以上 | CI |

## 9. 前提・制約

- 立ち上げは1名で開発し、その後、主催者へ引き渡す。チーム開発に移行する。
- 運用費用は、小さく保つ。ホスティングの利用規約上、無料の枠が使えない場合がある([ADR-0002](adr/0002-hosting-and-ownership.md))。
- 技術は、Next.js + Supabase + Stripeの自作とする([ADR-0001](adr/0001-tech-stack.md)、[ADR-0002](adr/0002-hosting-and-ownership.md))。開発・試作の環境はVercelとし、本番のホスティングは、引き渡し前に比較して決める([ADR-0002](adr/0002-hosting-and-ownership.md))。
- 構成は、**紹介サイト(物語・イベント・お問い合わせ・登録)**を先に作り、**販売**はその次の段階とする。
- 写真・ロゴ・ブランドの世界観は、主催者側と協力者の領域とする。CAMPFIREの画像は、主催者の許可により使用可(範囲は書面で確認)。
- 「アマゾンに負けない」は、目指す方向(ビジョン)とし、段階ごとの具体的な目標([第3章](#3-目標kpi案要合意))で進み具合を測る。最終的には、静岡県の生産者が参加できる産直サイトを目指す([フェーズ4](#将来フェーズ4-静岡県の生産者が参加する))。
