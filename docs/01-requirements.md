## この文書の書き方

### 書くもの、書かないもの

- このサイト(マーケットプレイス)の仕組み、つまりシステムがすることだけを書く。
- 運用の値(アプリケーション手数料の率の値、最初の生産者、運送会社の料金など)は、要件に書かない。議事録と操作手順書(05-operations.md)に置く。
- 技術の選定は ADR([docs/adr/](adr/))に書き、この文書に重ねて書かない。
- 言葉の意味は、1か所だけで決め、ほかの箇所では同じ言葉を使い、言い換えない。

### 要件の書き方

- 1つの要件には、1つの決まりだけを書く(1文1要件)。
- 要件は、次の列を持つ表で書く。

| 列 | 書くこと |
|---|---|
| ID | 下の「要件の ID」のとおり |
| 要件 | システムがすることを、1文で書く |
| 根拠 | なぜこの要件が必要か |
| 出典 | この要件が決まった議事録の名前か、ADR |
| 検証方法 | テスト、デモンストレーション、インスペクション、分析のどれか |
| 受入条件 | 何ができたら合格か |
| フェーズ | MVP か、それより後のどのフェーズか。フェーズの中身は「範囲とフェーズ」に書く |

- 要件から設計、テストへの対応表は、この文書には置かず、04-test.md に置く。
- 文書と項目の参照は、開発の進め方([CONTRIBUTING.md](../CONTRIBUTING.md))の「名前と番号の付け方(一覧)」の「文書の参照」の行のとおりにする。この文書の見出しは、重ならないようにする。

### 要件の ID

| 接頭辞 | 対象 | 書く章 | 例 |
|---|---|---|---|
| `FR-` | 機能要件 | 機能要件 | FR-001 |
| `NFR-` | 非機能要件 | 非機能要件 | NFR-001 |
| `TBD-` | 未確定事項 | 未確定事項 | TBD-001 |

- 番号は3桁とし、接頭辞ごとに 001 から、書いた順に付ける。章や節の並びとは関係させない。
- 文書の版が変わっても、同じ要件の ID は変えない。
- 要件を消すときは、行と ID を残して「削除」と書く。ID は使い回さない。

## 1. 範囲とフェーズ

### 1.1 フェーズの決まり

- フェーズは、リリースの段階である。工程(開発の進め方([CONTRIBUTING.md](../CONTRIBUTING.md))の「工程とゲート」)とは別のものである。
- フェーズの名前は、MVP、リリース2、リリース3 とし、この順にリリースする。
- 一度付けたフェーズの名前は、付け直さない。フェーズの中身や順を変えるときは、この文書の版を上げる。
- MVP の要件は、この文書の「機能要件」と「非機能要件」に詳しく書く。リリース2 とリリース3 は、「MVP の後のフェーズ」に中身だけを示し、要件は、そのフェーズに入るときに、この文書の版を上げて詳しく書く(開発の進め方([CONTRIBUTING.md](../CONTRIBUTING.md))の「リリースの単位」)。

### 1.2 範囲

このシステムは、生産者が商品を出品し(商品を、商品の一覧と商品ページに公開すること)、購入者が買い、代金が生産者に直接支払われるマーケットプレイスである。管理者は、場を提供する。アプリケーション手数料は、代金を確定するたびに、サイトを運営する側の Stripe のアカウント(プラットフォームのアカウント)が受け取る。

このシステムがしないこと:

- 代金を預かること。代金は、生産者に直接支払われ、プラットフォームのアカウントを通らない。
- 返金するかどうかや、返金の額、購入者と生産者の争いを判断すること。返金するかどうかは、生産者が、購入者と話し合って決める。
- 商品を配送すること。生産者が、運送会社を使って発送する。

方向性が決まっていないため、今の範囲に入れないもの(必要になれば、この文書の版を上げて追加する):

- 協賛・応援の案内

### 1.3 MVP

MVP は、購入者と生産者が、一般的なマーケットプレイスと同じ水準で、安心して快適に使い続けられる最初のリリースである。機能を MVP に入れるかは、次の問いで決める。

- その機能がないと、購入者か生産者が、このサイトを使わない、またはほかのサイトへ移るか。そうなら、MVP に入れる。
- 利用者が増えてから、または使われ方を見てから作るほうが、正しく作れるか。そうなら、後のフェーズに置く。

MVP で、それぞれの利用者ができること:

購入者

- 商品の一覧と商品ページ、生産者のページを見る。商品ページで、送り先の地域ごとの送料と、送料込みの合計を確かめる。
- 買う前に、生産者ごとの特定商取引法に基づく表記、商品の表示、返金と取り消しの決まりを確かめる。
- 会員として買うか、登録せずに買う。会員は、注文の履歴を見て、送り先の住所を保存でき、自分で退会できる。
- 注文ごとに、生産者とメッセージでやり取りし、返金を申し出る。
- 注文の画面から、管理者に問い合わせと、法律に基づく開示の請求を送り、管理者の返事をメールで受け取る。
- 注文の確認、発送(伝票番号)、返金、メッセージ、注文の取り消し(生産者が取り消したとき、代金の確定に失敗したとき、仮押さえの期限を過ぎたとき)の知らせを、メールで受け取る。

生産者

- 生産者のページの情報を登録する。商品を登録し、在庫を管理する。
- 新しい注文、メッセージ、返金の申し出、不審請求、仮押さえの期限が近いこと、仮押さえの期限で取り消した注文、「発送を知らせる」の押し忘れ、商品の非公開と非公開を解いたこと、停止と停止を解いたことの知らせを、メールで受け取る。
- 注文の代金を確定してから、商品を発送し、「発送を知らせる」を押す。
- メッセージに答え、返金の申し出に答え(返金する、または「返金しない」と答える)、必要なときは管理者に返金を頼み、不審請求(購入者がカード会社に、その支払いについて異議を申し立てること)に対応する。
- 生産者の画面から、管理者に問い合わせを送り、管理者の返事をメールで受け取る。
- 銀行口座と本人確認の情報を登録・更新し、売上と入金を確かめる。

管理者

- 生産者を登録し、停止し、停止を解く。
- オーナーは、生産者ごとのアプリケーション手数料の率を決める。
- 表示の誤りがある商品を非公開にし、非公開を解く。
- 運賃表を管理する。
- 問い合わせ、不審請求、生産者からの返金の依頼を、管理者の画面で確かめ、返金の依頼のとおりに返金する。
- 問い合わせに、管理者の画面から返事をする。法律に基づく開示の請求に答える。
- 管理者は、オーナーとスタッフに分かれる(「管理者、オーナー、スタッフ」のとおり)。オーナーは、スタッフを加え、外す。

サイト全体

- 問い合わせフォーム、措置のページ、利用規約(購入者向け、生産者向け)、プライバシーポリシーを置く。
- アクセス解析で、公開した時点から使われ方を測る。

### 1.4 MVP の後のフェーズ

リリース2: 購入者を集め、くり返し使ってもらう。MVP の時点では生産者が少ないため、まず購入者に来てもらい、また来てもらうことを先に行う。

- メールの配信と LINE 公式アカウントへの登録
- 管理者と生産者のお知らせ(成長の記録などの発信)
- イベントの一覧とイベントのページ
- 生産者のフォロー(お気に入り)
- 商品のレビュー

リリース3: 生産者と商品が増えたときに、広げる。

- 生産者が自分で参加を申し込む画面
- 商品の検索と絞り込み
- 体験・見学の予約
- 配送の希望日時
- 運送会社の伝票の作成
- 決済手段の追加(商品を送る前に代金を確定できるもの)
- カードの分割払い
- JCB、ダイナースクラブ、ディスカバーの受け付け(審査の結果の受け取りと、自動の返金への備えを含む)

## 2. 利用者と権限

### 2.1 利用者の種類

このサイトを使う人を、次の4つの種類に分ける。購入者は、登録していない人と会員のうち、商品を買う人をいう。

| 種類 | だれか | ログイン |
|---|---|---|
| 登録していない人 | 会員に登録せずにサイトを使う人。商品を見る人と、登録せずに買う購入者(ゲスト購入)を含む | 不要 |
| 会員 | 無料で登録し、ログインできる購入者 | 必要 |
| 生産者 | 商品を出品し、代金を自分の Stripe のアカウントで直接受け取る事業者。農産物などを生産する人のほか、自ら加工・開発した商品を販売する人を含む。会員のアカウントに付ける役割である(「アカウントと役割」のとおり) | 必要 |
| 管理者 | サイトを運営する人。オーナーとスタッフに分かれる(「管理者、オーナー、スタッフ」のとおり) | 必要 |

### 2.2 種類ごとの違いと、できないこと

それぞれの利用者が MVP でできることは、「MVP」のとおりである。この節には、「MVP」に書いていない、種類ごとの違いと、できないことを書く。

登録していない人

- 自分の注文は、注文の確認のメールのリンクから開く。
- できない: 注文の履歴を一覧で見ること。送り先の住所を保存すること。

会員

- 退会すると、ログインできなくなる。生産者の役割を持つ会員は、生産者として受けた注文に、発送も取り消しもしていない注文、閉じていない返金の申し出、結果が出ていない不審請求、メッセージを送れる期間が終わっていない注文が残っておらず、最後の発送から、NFR-003 の期間がたったときに退会できる(一度も発送していなければ、期間を待たない)。退会すると、生産者の役割も外れる。退会したあとに残す記録と、退会のときに消す情報は、NFR-004〜NFR-006、NFR-008 のとおりである。
- できない: ほかの会員の情報と注文を見ること。

生産者

- できない: ほかの生産者の注文と売上を見ること。ほかの生産者の商品を変えること。運賃表とアプリケーション手数料の率を変えること。

管理者

- サイトという場の運営(どの生産者に場を貸すか、表示の決まりを守らせること、法律に基づく請求と要請への対応、アプリケーション手数料の率と運賃表)を判断する。管理者の仕事が注文の数に比例して増えないよう、注文ごとの作業は、システムと生産者が受け持つ。
- できない: 返金するかどうかや、返金の額、購入者と生産者の争いを判断すること(「範囲」のとおり)。

### 2.3 管理者、オーナー、スタッフ

- 管理者は、オーナーとスタッフに分ける。
- オーナーは、つねに1人だけいる。
- オーナー以外の管理者を、スタッフとする。スタッフは、複数人を置ける。
- オーナーは、管理者ができることのすべてに加え、次のことができる。スタッフは、これらができない。
  - 生産者ごとのアプリケーション手数料の率を決め、変える。
  - スタッフを加え、外す。まだ受けられていないスタッフの招待を取り消す(FR-232)。スタッフの2段階認証の手段の登録を消す(FR-235)。
  - オーナーを、新しいオーナーに引き継ぐ。管理者でない人に引き継ぐときは、先にスタッフとして加える。
- サイトを使い始めるときに、最初のオーナーを1人作る。作る手順は、操作手順書に書く。

### 2.4 アカウントと役割

- 1人が、複数の種類を兼ねてよい(例: 管理者が、生産者を兼ねる。生産者が、購入者として買う)。
- 生産者は、会員のアカウントに付ける役割とする。生産者の役割を持つ会員は、同じアカウントで、出品も買い物もできる。
- 管理者のアカウントは、会員のアカウントとは別のメールアドレスで作り、管理の仕事にだけ使う。管理者のアカウントでは、買うことも出品することもできない。管理者が買うときや生産者を兼ねるときは、別のメールアドレスの会員のアカウントを使う。買うときは、登録せずに買ってもよい。
- 管理者が生産者を登録するときは、メールアドレスを指定し、本人に生産者の招待のメールを送る。本人が生産者向けの利用規約に同意したときに限り、そのメールアドレスの会員のアカウントに生産者の役割を付ける。会員のアカウントがなければ、同意のときに作る。このときは、購入者向けの利用規約とプライバシーポリシーへの同意も求める(FR-212)。
- 管理者が生産者を停止すると、その生産者の新しい出品と、新しい注文の受け付けが止まる。すでにある注文の対応と、会員としての買い物を含め、そのほかの機能は止まらない。

### 2.5 ログイン

- 会員(生産者の役割を持つ会員を含む)と管理者は、メールアドレスとパスワードでログインする。
- 生産者の役割を持つ会員は、ログインしたあと、同じアカウントのまま、生産者の画面に移れる。
- 管理者は、会員とは別の入口からログインする。
- 生産者の役割を持つ会員と管理者のログインには、2段階認証を必ず求める。2段階認証の方法は、NFR-001 のとおりである。
