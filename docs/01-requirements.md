## この文書の書き方

### 書くもの、書かないもの

- このサイト(マーケットプレイス)の仕組み、つまりシステムがすることだけを書く。
- 運用の値(率の値、最初の生産者、運送会社の料金など)は、要件に書かない。議事録と操作手順書(05-operations.md)に置く。
- 技術の選定は ADR([docs/adr/](adr/))に書き、この文書に重ねて書かない。
- 言葉の意味は、その言葉を最初に使うところで決める。

### 要件の書き方

- 1つの要件には、1つの決まりだけを書く(1文1要件)。
- 要件は、次の列を持つ表で書く。

| 列 | 書くこと |
|---|---|
| ID | 下の「要件の ID」のとおり |
| 要件 | システムがすることを、1文で書く |
| 根拠 | なぜこの要件が必要か |
| 出典 | この要件が決まった議事録の名前か、ADR |
| 検証方法 | テスト、デモンストレーション、インスペクション、分析のどれか |
| 受入条件 | 何ができたら合格か |
| フェーズ | MVP か、それより後のどのフェーズか。フェーズの中身は「範囲とフェーズ」に書く |

- 要件から設計、テストへの対応表は、この文書には置かず、04-test.md に置く。
- 文書と項目の参照は、開発の進め方([CONTRIBUTING.md](../CONTRIBUTING.md))の「名前と番号の付け方(一覧)」の「文書の参照」の行のとおりにする。この文書の見出しは、重ならないようにする。

### 要件の ID

| 接頭辞 | 対象 | 書く章 | 例 |
|---|---|---|---|
| `FR-` | 機能要件 | 機能要件 | FR-001 |
| `NFR-` | 非機能要件 | 非機能要件 | NFR-001 |
| `TBD-` | 未確定事項 | 未確定事項 | TBD-001 |

- 番号は3桁とし、接頭辞ごとに 001 から、書いた順に付ける。章や節の並びとは関係させない。
- 文書の版が変わっても、同じ要件の ID は変えない。
- 要件を消すときは、行と ID を残して「削除」と書く。ID は使い回さない。

## 1. 範囲とフェーズ

### 1.1 フェーズの決まり

- フェーズは、リリースの段階である。工程(開発の進め方([CONTRIBUTING.md](../CONTRIBUTING.md))の「工程とゲート」)とは別のものである。
- フェーズの名前は、MVP、リリース2、リリース3 とし、この順にリリースする。
- 一度付けたフェーズの名前は、付け直さない。フェーズの中身や順を変えるときは、この文書の版を上げる。
- MVP の要件は、この文書の「機能要件」と「非機能要件」に詳しく書く。リリース2 とリリース3 は、この章に中身だけを示し、要件は、そのフェーズに入るときに、この文書の版を上げて詳しく書く(開発の進め方([CONTRIBUTING.md](../CONTRIBUTING.md))の「リリースの単位」)。

### 1.2 範囲

このシステムは、生産者が商品を出品し、購入者が買い、代金が生産者に直接支払われるマーケットプレイスである。管理者は、場を提供し、決済のたびにアプリケーション手数料を受け取る。

このシステムがしないこと:

- 代金を預かること。代金は、生産者に直接支払われ、管理者を通らない。
- 返金や、購入者と生産者の争いを判断すること。返金は、生産者と購入者の話し合いで決まる。
- 商品を配送すること。生産者が、運送会社を使って発送する。

方向性が決まっていないため、今の範囲に入れないもの(必要になれば、この文書の版を上げて追加する):

- 協賛・応援の案内
- 応援会員(会員ページ、月額の課金)。追加するときは、生産者が売る商品の1つ(月額で課金する商品)とする。追加に備え、商品の種類をあとから足せる設計にする。Stripe で月額の課金を生産者のアカウントに作れるかは、追加するときに、テスト環境で確かめる。

### 1.3 MVP

MVP は、購入者と生産者が、一般的なマーケットプレイスと同じ水準で、安心して快適に使い続けられる最初のリリースである。機能を MVP に入れるかは、次の問いで決める。

- その機能がないと、購入者か生産者が、このサイトを使わない、またはほかのサイトへ移るか。そうなら、MVP に入れる。
- 利用者が増えてから、または使われ方を見てから作るほうが、正しく作れるか。そうなら、後のフェーズに置く。

MVP で、それぞれの利用者ができること:

購入者

- 商品の一覧と詳細、生産者のページを見る。商品ページで、送り先の地域ごとの送料と、送料込みの合計を確かめる。
- 買う前に、生産者ごとの特定商取引法に基づく表記、商品の表示(食品や化粧品に必要な表示)、返金とキャンセルの決まりを確かめる。
- アカウントを作って買うか、アカウントを作らずに買う(ゲスト購入)。アカウントでは、注文の履歴を見て、送り先の住所を保存できる。
- 注文ごとに、生産者とメッセージでやり取りし、返金を申し出る。
- 注文の確認、発送(伝票番号)、返金、メッセージの知らせを、メールで受け取る。

生産者

- 自分のページを書き、商品を登録し、在庫を管理する。
- 新しい注文とメッセージの知らせを、メールで受け取る。
- 注文を発送する。発送のときに、代金が確定する。
- メッセージに答え、返金し、不審請求に対応する。
- 銀行口座と本人確認の情報を登録・更新し、売上と入金を確かめる。
- 自分の商品と注文だけを扱い、ほかの生産者のデータは見えない。

管理者

- 生産者を登録し、停止する。
- 運賃表と、生産者ごとのアプリケーション手数料の率を管理する。
- 問い合わせを確かめ、生産者の依頼で返金する。

サイト全体

- 問い合わせフォーム、利用規約(購入者向け、生産者向け)、プライバシーポリシーを置く。
- アクセス解析で、公開した時点から使われ方を測る。

### 1.4 MVP の後のフェーズ

リリース2: 購入者を集め、くり返し使ってもらう。MVP の時点では生産者が少ないため、まず購入者に来てもらい、また来てもらうことを先に行う。

- メールと LINE の登録
- 管理者と生産者のお知らせ(成長の記録などの発信)
- イベントの一覧と詳細
- 生産者のフォロー(お気に入り)
- 商品のレビュー

リリース3: 生産者と商品が増えたときに、広げる。

- 生産者が自分で参加を申し込む画面
- 商品の検索と絞り込み
- 体験・見学の予約
- 配送の希望日時
- 運送会社の伝票の作成
- 決済手段の追加(仮押さえに対応するもの)
- カードの分割払い
